# Development Instructions for AI Agents - Solucimob Calc

> Guidelines for AI-assisted development of the calculation microservice.

## 🎯 Project Overview

- **Purpose**: Real estate calculations and metrics microservice
- **Type**: Express.js REST API (Node.js)
- **Tech Stack**: JavaScript, Express, MongoDB, Jest
- **Build**: npm scripts

---

## 🏗 Architecture Pattern

**Layered Architecture** with microservice patterns:
- **Controller**: HTTP request handling
- **Service**: Business logic and calculations
- **Repository**: MongoDB data persistence
- **Middleware**: Error handling, validation
- **External**: Config Service client

### Core Components
```
Routes        - Express endpoints
Controllers   - Request/response handling
Services      - Business logic and calculations
Models        - MongoDB schemas
Middleware    - Error handling, validation
Clients       - Config service HTTP client
```

---

## 📂 File Naming & Conventions

**Files**: camelCase
- `calculationService.js`, `propertyController.js`, `configService.js`

**Routes**: `/api/resource/action` pattern
- `/api/property/valuation`, `/api/metrics/analyze`

**Methods**: camelCase
- `calculateValuation()`, `getValuationRules()`, `validateProperty()`

**Variables**: descriptive camelCase
- `propertyData`, `valuationRules`, `calculatedValue`

---

## ✅ DO's

1. **DO** call config service for global rules and parameters
2. **DO** validate input before calculations
3. **DO** cache config rules to reduce API calls
4. **DO** return consistent response format
5. **DO** implement error handling with proper status codes

---

## ❌ DON'Ts

1. **DON'T** hardcode calculation rules (fetch from config)
2. **DON'T** skip input validation
3. **DON'T** expose database errors to clients
4. **DON'T** make blocking calculations for large datasets
5. **DON'T** ignore config service failures

---

## 📋 Common Workflows

**Adding new calculation endpoint**:
1. Create route in `routes/calculations.js`
2. Create controller method
3. Fetch rules from config service
4. Implement calculation in service
5. Save result to MongoDB
6. Return formatted response
7. Add unit and integration tests

**Integration with Config Service**:
1. Create `configService.js` with HTTP client
2. Implement methods: `getValuationRules()`, `getParameters()`
3. Add caching for performance
4. Handle network failures gracefully
5. Retry logic for resilience

**Error handling pattern**:
```javascript
try {
  const rules = await configService.getValuationRules();
  const result = calculateValuation(property, rules);
  res.json({ success: true, data: result });
} catch (error) {
  logger.error(error);
  res.status(500).json({
    success: false,
    error: error.message,
    code: 'CALCULATION_ERROR'
  });
}
```

**Testing calculations**:
```bash
npm test                          # Run all tests
npm test -- --coverage          # Generate coverage report
npm run dev                      # Start development server
```
